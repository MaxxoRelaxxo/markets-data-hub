# Markets Data Hub

Data pipeline that collects, validates, and visualizes Swedish financial market data. Built with [Dagster](https://dagster.io/) and hosted on Dagster Cloud Serverless. Includes a React frontend dashboard and a Marimo interactive notebook.

## Data sources and assets

The project contains four assets in the **Market_operations** group:

| Asset | Description | Source | Schedule |
|---|---|---|---|
| `riksbank_certificate` | Auction results for Riksbank certificates (offered/allocated volume, interest rate, ISIN, etc.) | Web scraping of the Riksbank website | Tuesdays 10:40 UTC |
| `sales_of_gov_bonds` | Auction results for government bonds (SGB) and inflation-linked government bonds (SGB IL) | Web scraping of the Riksbank website | Fridays 10:40 UTC |
| `get_swestr_values` | SWESTR rates (interest rate, percentile spread, volume, number of transactions) | Riksbank SWESTR API | Weekdays 09:05 UTC |
| `get_policy_rate_values` | Riksbank policy rate (SECBREPOEFF series) | Riksbank SWEA API | Weekdays 09:05 UTC |

### Supplementary data files

| File | Description |
|---|---|
| `Reserver.xlsx` | Historical reserves from the Riksbank balance sheet (1999–2023). Used to replace calculated reserves for 2018-12-18 to 2023-02-07. |
| `Finjusterade_transaktioner.xlsx` | Fine-tuning transactions discontinued on 2019-10-09 |
| `ref_rgk.xlsx` | Reference data for government bond ISINs (Riksgälden) |

All data is validated with Pydantic schemas, transformed with Polars, and stored as Parquet files.

## Interactive analysis

A [Marimo](https://marimo.io/) notebook (`src/markets_data_hub/notebooks/analysis.py`) visualizes the collected data:

- **Riksbank certificates** -- key metrics from the latest auction, bank system liquidity position over time
- **Government bonds** -- bid-to-cover ratio per auction for SGB and SGB IL
- **Short-term money market** -- current SWESTR rate, spread box plots, SWESTR vs policy rate over time
- **Interest rates** -- MFI lending and deposit rates to households, NFC lending rates

Run the notebook with:

```bash
marimo run src/markets_data_hub/notebooks/analysis.py
```

## React frontend

The frontend is a React dashboard that displays the same data as the notebook in a web-friendly format. Data is served as static JSON/CSV files generated by the build script.

### Building frontend data

After the Dagster pipeline has produced new Parquet files, regenerate the frontend JSON/CSV:

```bash
python scripts/build_data.py
```

This reads Parquet and Excel files from `src/markets_data_hub/data/` and writes JSON/CSV to `frontend/public/data/`.

### Running the frontend locally

```bash
cd frontend
npm install
npm run dev
```

### Verification in Codespaces

After cloning or pulling changes in a GitHub Codespace, verify everything works:

```bash
# 1. Install Python dependencies
pip install -e ".[dev]"

# 2. Run tests
pytest tests

# 3. Rebuild frontend data from Parquet/Excel sources
python scripts/build_data.py

# 4. Verify reserves data was correctly replaced (spot-check)
python -c "
import json
with open('frontend/public/data/cert_data.json') as f:
    data = json.load(f)
ts = {d['date']: d for d in data['timeseries']}
# These should use Reserver.xlsx values (not Erbjuden-Tilldelad)
print('2018-12-18 reserves:', ts.get('2018-12-18', {}).get('aterstaende'))
print('2023-02-07 reserves:', ts.get('2023-02-07', {}).get('aterstaende'))
# This should use calculated value (outside replacement range)
print('2023-02-14 reserves:', ts.get('2023-02-14', {}).get('aterstaende'))
print('Latest entry:', data['timeseries'][-1]['date'], data['timeseries'][-1]['aterstaende'])
"

# 5. Start the frontend dev server (port auto-forwards in Codespaces)
cd frontend
npm install
npm run dev

# 6. (Optional) Run the Marimo notebook
marimo run src/markets_data_hub/notebooks/analysis.py

# 7. (Optional) Run the full Dagster pipeline locally
dagster dev
```

## Getting started

### Prerequisites

- Python >= 3.10, < 3.15
- Node.js >= 18 (for the React frontend)
- A Riksbank API key (for the SWESTR and SWEA APIs)

### Installation

```bash
pip install -e ".[dev]"
```

### Environment variables

| Variable | Description |
|---|---|
| `RIKSBANK_API_KEY` | API key for the Riksbank SWESTR and SWEA APIs |

### Running Dagster locally

```bash
dagster dev
```

Open http://localhost:3000 in your browser.

## Tests

```bash
pytest tests
```

## Tech stack

- **Dagster** -- orchestration and scheduling
- **Polars** -- data transformation
- **Pydantic** -- data validation
- **BeautifulSoup4** -- web scraping
- **Marimo + Altair** -- interactive visualization (notebook)
- **React + Recharts** -- frontend dashboard
- **Parquet** -- data storage

## Project structure

```
src/markets_data_hub/
  definitions.py          # Jobs, schedules, and resource definitions
  assets/
    assets.py             # Asset definitions (data pipelines)
    schemas.py            # Pydantic models
    frontend.py           # Frontend build asset
  utils/
    constants.py          # Key mappings for data transformation
    functions.py          # Scraping and API functions
  notebooks/
    analysis.py           # Marimo notebook for visualization
  data/                   # Generated Parquet files + supplementary Excel
scripts/
  build_data.py           # Convert Parquet/Excel → JSON/CSV for frontend
  fetch_data.py           # Manual data fetching
frontend/
  src/
    App.jsx               # Main React app with tabbed layout
    components/
      CertificateSection.jsx  # Riksbank certificates + liquidity graph
      SwestrSection.jsx       # SWESTR reference rate analysis
      BondsSection.jsx        # Government bond auctions
      ScbRatesSection.jsx     # SCB interest rates
  public/data/            # Generated JSON/CSV consumed by the frontend
tests/
  test_assets.py          # Unit tests for assets
  test_defs.py            # Tests for pipeline definitions
```

## Deployment

The project deploys automatically to [Dagster Cloud Serverless](https://dagster.io/cloud) via GitHub Actions:

- **Push to main** -- production deploy (`deploy.yml`)
- **Push to feature branch** -- branch deploy (`branch_deployments.yml`)
